# Environment

Use a dedicated Python 3.11 environment. The scripts need NumPy, pandas,
SciPy, scikit-learn, PyTorch, XGBoost and requests; no API key is needed by
the three main experiments. Raw OSM acquisition additionally invokes the
system `curl` executable.

`requirements.txt` lists direct dependencies with broad version bounds.
It is not an exact historic lock, and successful installation is not proof
of numerical identity across releases or devices.

The saved original Transformer run manifest records PyTorch 2.8.0 and CPU.
The retained local vendor distributions include XGBoost 3.0.5; that fact
alone is not a complete per-run environment record. Vendor directories
are not redistributed.

Release smoke checks use the already-installed local Python environment.
Its exact observed versions are in `release_environment.json`. That file
describes the release check, **not** the full historical training environment.
No packages were installed or upgraded during release preparation.
The corresponding direct-package pins are in `requirements-tested.txt`.
This is not a transitive dependency lock; installability on other platforms
has not been verified.
In this local environment, sequential PyTorch backpropagation followed by an
XGBoost fit crashed in one combined process; isolated fits passed. The smoke
test runs XGBoost in a subprocess, and the documented training stages are
separate commands. See RELEASE_CHECKS.md for the verification boundary.

The release defaults to CPU to match the saved main-run manifest.
An explicit `PROPERTY_DEVICE=mps` or `PROPERTY_DEVICE=cuda` selects another
available device, but changes numerical and reproducibility conditions.
Use only checkpoints generated by yourself or another trusted source:
the original runners load full PyTorch checkpoint objects.

Some training scripts reuse existing metadata/checkpoints. Run a new
configuration in a fresh working copy/output directory rather than mixing
stale outputs from a different data snapshot, environment or configuration.
